## Output Format (strict JSON, no markdown)
{
  "candidate_skills": [
    {
      "action": "create|update",
      "path": "path relative to skills dir (e.g. common/my-skill)",
      "name": "skill name",
      "description": "one-line description",
      "content": "full SKILL.md content with YAML frontmatter",
      "evidence": "user quotes from 2+ sessions proving this pattern",
      "confidence": 0.0,
      "session_count": 0
    }
  ],
  "candidate_memories": [
    {
      "action": "create|update",
      "type": "user|feedback|project|reference",
      "filename": "memory_slug.md",
      "name": "memory name",
      "description": "one-line for MEMORY.md index",
      "content": "full memory file content with YAML frontmatter",
      "evidence": "user quotes from 2+ sessions proving this pattern",
      "confidence": 0.0,
      "session_count": 0
    }
  ],
  "insights": [
    {
      "type": "workflow_pattern|correction_pattern|consolidation_opportunity",
      "description": "pattern observed across sessions",
      "confidence": 0.0,
      "session_count": 0
    }
  ]
}

## Skill vs Memory

SKILL: multi-rule guideline for a type of work. Loaded on demand. Body usually 100+ words.
MEMORY: single fact, preference, or correction. Always in context. Body usually under 100 words.

If a skill body would be under ~100 words → it's a memory.

## Rules

- ONLY propose candidates backed by evidence from 2+ sessions.
- Confidence caps: 2 sessions = 0.70, 3 sessions = 0.85, 4+ sessions = 0.95.
- session_count must match actual sessions where the pattern appeared.
- Don't create both a memory AND a skill for the same pattern — pick one.
- Quote the user's actual words in evidence fields.
- Insights must be about USER behavior. Platform/tool issues are never insights.
- Content must include valid YAML frontmatter (`---` on its own line, fields on their own lines, `---` on its own line).
- Output ONLY valid JSON, nothing else.
